# dpiphone: диагностика блокировок с iPhone одной кнопкой

Обёртка над [dpi-detector](https://github.com/Runnin4ik/dpi-detector) для терминала
a-Shell mini. Команда (Shortcuts) запускает движок, показывает короткий отчёт с
вердиктом и кладёт полный лог и JSON в iCloud Drive, в папку `DPI Logs`.
Описание проекта: `docs/superpowers/specs/2026-11-02-dpi-ios-design.md`.

## Установка на iPhone

1. Поставить **a-Shell mini** из App Store.
2. В a-Shell:

```
lg2 clone <адрес репозитория> ~/Documents/dpiphone
cd ~/Documents/dpiphone
sh install.sh
```

`install.sh` это семь строк без условий: клонирует движок в `~/Documents/dpi-detector`,
переключает его на закреплённый коммит из `engine.lock`, ставит зависимости, создаёт
`out/` и `history/`. Если `sh install.sh` в a-Shell не сработает, выполните его строки
по одной вручную. Если движок уже клонирован в `~/Documents/dpi-detector`, первую
строку пропустите.

## Команды (Shortcuts)

Три Команды, одинаковые по устройству, различаются режимом. Действия по порядку:

1. **Получить сведения о сети** → переменная `Сеть`: SSID Wi-Fi, а если его нет,
   имя оператора. Если пусто, подставьте текст `unknown`.
   Затем **Заменить текст**: убрать из `Сеть` символы `"` и `$`, иначе строка
   команды в a-Shell ломается.
2. **a-Shell: Выполнить команду**, режим «в приложении», текст из шести строк
   (вместо `<Сеть>` вставьте переменную, вместо `<тесты>` и `<режим>` значения из
   таблицы ниже). Вторая строка убирает файлы прошлого прогона, чтобы Команда не
   показала старый отчёт, если обёртка не запустилась; третья задаёт ширину
   терминала, иначе на узком экране движок обрежет таблицы и отчёт скажет «лог
   нечитаем» (если a-Shell ругается на `export`, замените на `setenv COLUMNS 120`):

```
cd ~/Documents/dpiphone
rm -f out/summary.txt out/name.txt out/last.log out/last.json
export COLUMNS=120
python ../dpi-detector/dpi_detector.py -t <тесты> --batch -c 20 -o out/raw.log > out/console.log 2>&1
python report.py --mode <режим> --net "<Сеть>"
open shortcuts://
```

3. **a-Shell: Получить файл** `~/Documents/dpiphone/out/summary.txt` → **Показать результат**.
4. **a-Shell: Получить файл** `~/Documents/dpiphone/out/name.txt` → переменная `Имя`.
5. **a-Shell: Получить файл** `~/Documents/dpiphone/out/last.log` → **Сохранить файл**
   в iCloud Drive, путь `DPI Logs/<Имя>.log`, «Спрашивать, куда сохранить» выключено.
6. То же для `out/last.json` → `DPI Logs/<Имя>.json`.

| Команда              | режим | тесты | что делает                                   | время, трафик        |
|----------------------|-------|-------|----------------------------------------------|----------------------|
| Сеть: быстро         | quick | 0123  | сеть и ASN, DNS, домены, обрыв 16–20 КБ      | ~1–2 мин, мало       |
| Сеть: полностью      | full  | 01235 | то же плюс Telegram (30 МБ + 10 МБ)          | ~3–5 мин, десятки МБ |
| Сеть: белые SNI      | sni   | 34    | обрыв 16–20 КБ и перебор белых SNI           | при белом списке 10+ мин |

Перед запуском выключите VPN и обходчики: иначе прогон покажет сеть VPN-сервера, а
не вашего оператора. Обёртка это замечает (вердикт «похоже, включён VPN») и такой
прогон не берёт за базу для сравнения.

## Как читать отчёт

Первая строка это вердикт, ниже факты, на которых он основан, последняя строка
сравнение с прошлым прогоном на той же сети.

| Вердикт | Что это значит |
|---------|----------------|
| Всё в порядке | Блокировок сверх обычных нет, канал отвечает. |
| Похоже, включён белый список | Половина и больше зарубежных хостингов обрываются после 16–20 КБ, минимум три провайдера целиком. |
| Появились новые блокировки | По сравнению с прошлым прогоном на этой сети минимум три новых домена режутся DPI. |
| Оператор начал подменять DNS | Подмена ответов появилась, в прошлом прогоне её не было. Если она была всегда, это строка фактов, не вердикт. |
| Блокировок не вижу, похоже на качество канала | Четверть и больше целей молча не отвечают, или Telegram замедлен, а активных блокировок нет. |
| Похоже, включён VPN или прокси | FakeIP в DNS или другой оператор (ASN), чем в прошлый раз. |
| Сеть почти не отвечает | Нет внешнего IP, движок упал или всё в таймаутах. |

Правила намеренно строгие: при сомнении отчёт говорит «всё в порядке», а
подозрительное остаётся в строках фактов. Пороги в `dpiphone/thresholds.py`.

## Логи для анализа

После прочтения обёртка переименовывает `out/raw.log` и `out/console.log` в `*.prev.log`:
движок пишет `raw.log` только в самом конце, и без этого упавший прогон подхватил бы
лог прошлого. Каждый прогон оставляет в iCloud Drive/DPI Logs два файла:
`2026-11-02_14-32_quick_MTS.log` (полный вывод движка с шапкой) и такой же `.json`
(разобранный результат, вердикт, отличия от базы). Их можно отдавать Claude на
разбор целыми пачками: по имени видно дату, режим и сеть.

## Разработка на Mac

```
python3 -m venv venv && venv/bin/pip install -r requirements-dev.txt
venv/bin/python -m pytest -q
```

Живой прогон на Mac: движок в любой папке на коммите из `engine.lock` с его
зависимостями (`pip install -r requirements.txt`), затем

```
python <движок>/dpi_detector.py -t 0123 --batch -c 20 -o out/raw.log > out/console.log 2>&1
python report.py --mode quick --net "Mac" --engine <движок>
```

Синтетические фикстуры тестов пересобираются скриптом `tests/fixtures/make_synthetic.py`
(нужен пакет `rich`).

## Обновление движка

1. Сменить хэш в `engine.lock`.
2. На Mac: `git checkout <хэш>` в папке движка, прогнать `pytest`. Парсер завязан на
   формат вывода, при расхождениях чинить `dpiphone/parse.py` и фикстуры.
3. На телефоне: `cd ~/Documents/dpi-detector && lg2 fetch && lg2 checkout <хэш>`.
